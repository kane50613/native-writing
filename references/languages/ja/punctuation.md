# 日本語の記号と場面

まず、文章がどこに表示されるかを確かめます。チャットの一言、ヘルプの手順、技術ブログ、画面のボタンでは、句点や記号の使い方が違います。

## 場面ごとの起点

| 場面 | 書き方の起点 |
| --- | --- |
| 書籍、小説、編集された文章 | 文を句点で終え、出版社の表記に従います。会話の「」や、ダッシュ、三点リーダーで表す間を残します。 |
| ブログ、技術記事 | 段落に分け、文ごとに句点を打ちます。書き手が半角の「?」や丸括弧を一貫して使っていれば、そのままにします。 |
| チャット、短い返信 | 一つの発言で意味が完結していれば、末尾の句点はなくてもかまいません。長い依頼は文を区切ります。 |
| ヘルプ、ドキュメント | 文は句点で終えます。手順、条件、注意はそれぞれ別の文に分けます。 |
| ボタン、見出し、項目名 | 句点を付けません。完全な文になっている説明やツールチップには、一文でも句点を付けます。 |

## 記号ごとの判断

| 記号 | 使い方 |
| --- | --- |
| 句点 `。`、読点 `、` | 日本語の文の基本です。横書きの公用文では読点に `，` も認められていますが、一つの文書でどちらかにそろえます。プロダクトの文言では `、` が一般的です。中国語の全角コンマ `，` が混じっていたら `、` に直します。 |
| かぎ括弧 `「」`、二重かぎ括弧 `『』` | 「」は引用、画面に出る文言、入力してほしい値、強調したい語に使います。「」の中にさらに引用があるときは『』にします。書名を『』で示す体裁もあります。 |
| 角括弧 `[ ]`、`［ ］` | 手順の中でボタンやメニューの名前を示すときに使う体裁があります（Microsoft、Google、SmartHR）。Apple やメルカリは同じ用途に「」を使います。プロジェクトの既存の手順にそろえます。 |
| 丸括弧 `（）` | 補足に使います。全角にするか半角にするかは書き手や製品によって違うので、一つの文章の中でそろえます。読み手が必ず知るべき条件は、括弧に入れずに本文で書きます。 |
| 疑問符 `？`、感嘆符 `！` | 確認ダイアログの「〜しますか？」には付けます。全角か半角かはプロジェクトに合わせます。後ろに文が続くときは、記号の後に 1 文字分空けます。説明文で `！` を多用すると押しつけがましく見えるので、告知やお祝いの一言だけに使います。 |
| 中点 `・` | 外国の人名や複合語（トリニダード・トバゴ）と、順番を入れ替えてもよい並列（企画・運営）に使います。順番に意味がある列挙は `、` にします。 |
| 波ダッシュ `〜` | 範囲を表します（10:00〜12:00）。数値の範囲は「0 から 99 まで」と書いた方が誤解されません。「〜してください」のように文の型を示すために使う `〜` は、範囲ではありません。 |
| コロン `：`、`:` | 「例：」「注：」「日時：」のようなラベルと値の区切りに使います。時刻（12:30）は半角です。文の途中で説明を導くためにコロンを重ねず、文で書きます。 |
| 三点リーダー `…` | 言いかけや省略を表します。編集された文章では `……` のように二つ並べます。ボタンの「名前を付けて保存...」のように、続きの操作があることを示す `...` はそのまま残します。 |
| ダッシュ `―` | 言いよどみや挿入に使います。日本語のプロダクトの文言ではほとんど使いません。説明文では文を分けて書きます。 |
| スラッシュ `/` | 日付の区切り（2024/3/14）と対になる語（オン/オフ）に使います。 |

URL、パス、コード、バージョン番号（v1.2）、小数、英語の引用は、全角に置き換えません。

## 和欧間のスペース

日本語と英字・数字の間に半角スペースを入れるかどうかは、製品によって分かれています。

- 入れる例は Microsoft の翻訳ガイド（「Word を使用する」）、Google のヘルプ（「Google アカウント」）、個人の技術ブログ（「Web のセマンティクス」）です。
- 入れない例は Apple のサポート（「Apple Accountにサインイン」）、メルカリのヘルプ（「2次元コード」）、SmartHR の表記ルール（「PDFファイル」）、サイボウズの開発者ブログ（「LT会」）です。

プロジェクトや文書に決まった書き方があれば、それに従います。なければ既存の文言を数えて多い方に合わせ、一つのファイルや画面の中で混ぜないようにします。どちらの場合も、句読点や括弧と英数字の間には空けません（「v2 に更新しました。」の「。」の前など）。

組版の上では、和文と欧文の間はおよそ四分の一字分空けるものとされています。CSS の `text-autospace` などで自動的に空けている画面では、手で空白を入れると間隔が二重になります。

## 自作の対照例

- チャット：`了解です、明日送ります` は句点なしで足ります。
- ヘルプ：`ファイルを選択します。[アップロード] をクリックします。`
- 小説：`「てっきり……」彼女は口をつぐんだ。` と `「てっきり――」チャイムが鳴った。` は、間の種類が違います。
- ボタンと見出し：見出しは `アップロードの完了`、説明は `ファイルを処理しています。`、ボタンは `ファイルを表示` です。

元の文の意味と気持ちを保ちます。長い説明を断片の羅列にせず、短い返信を公文書のように書き直さないでください。

## 参考

- 文化庁、[公用文作成の考え方（建議）（2022）](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93731901_01.pdf)、「符号の使い方」。句読点、括弧と句点の位置、「？」「！」の後の 1 字空け、コロンやダッシュの用法を定めています。公用文の基準で、くだけた文章の習慣を表すものではありません。
- Microsoft、[Japanese Localization Style Guide](https://download.microsoft.com/download/a/8/2/a822a118-18d4-4429-b857-1b65ab388315/jpn-jpn-StyleGuide.pdf)、4.1.9 Punctuation と 4.1.11 Symbols & spaces。全角と半角の使い分け、和欧間に半角スペースを入れる規則、UI 名を [ ] で示す規則、範囲の `～` を「から」に置き換える規則があります。
- SmartHR Design System、[記号（括弧、句点、スペースなど）の表記](https://smarthr.design/products/contents/idiomatic-usage/symbol/)。和欧間にスペースを入れない規則、見出しの句点を省く規則、文になっていれば句点を付ける規則、`・` と `、` の使い分けがあります。
- W3C、[Requirements for Japanese Text Layout](https://www.w3.org/TR/jlreq/) 3.2.6。和文と欧字・アラビア数字の字間を四分アキとし、行頭と行末では空けないとしています。
- [Google アカウント ヘルプ](https://support.google.com/accounts/answer/41078?hl=ja)、[Apple サポート 102656](https://support.apple.com/ja-jp/102656)、[メルカリ ガイド](https://help.jp.mercari.com/guide/articles/1083/)。和欧間のスペースと UI 名の括弧について、製品ごとに違う書き方をしている例です。
- Jxck、[Web のセマンティクスにおける Push と Pull（2021）](https://blog.jxck.io/entries/2021-12-08/web-semantics-push-and-pull.html)と、サイボウズ、[QAメンバーで「ハードルの低いLT会」を開催したら社内勉強会に発展しました（2021）](https://blog.cybozu.io/entry/2021/12/22/143508)。前者はだ・である調で、半角の「?」と丸括弧を使い、和欧間にスペースを入れます。後者はです・ます調で、スペースを入れません。

これらは書き方の幅を示す例で、使用頻度の統計ではありません。
