# 日本語

[記号と場面](punctuation.md)もあわせて読みます。

日本の読み手が普段目にしている日本語で書きます。文体と丁寧さは、文章が表示される場所で決めます。ヘルプや通知は丁寧に、ボタンや見出しは短く書きます。ブログは書き手の口調を残します。プロジェクトの表記ルールや既存の文言があれば、そちらに合わせます。

## 書き方

**文体は表示される場所で決め、同じ場所の中ではそろえます。** 日本のプロダクトやヘルプでは、場所ごとに次の文体がよく使われています。

| 場所 | 文体 | 例 |
| --- | --- | --- |
| 説明文、通知、エラーの本文、ヘルプ、メール | です・ます調。操作を促すときは「〜してください。」 | 「ファイルを保存できませんでした。もう一度お試しください。」 |
| ボタン、メニュー、タブ | 動詞の終止形か、サ変名詞だけ | 「保存」「削除」「権限を追加」「申請を取り消す」 |
| 見出し、画面名、項目名、表の列名 | 名詞で終える（体言止め） | 「権限の追加」「申し込み日時」 |
| エラーやダイアログのタイトル | 句点のない短い文か名詞 | 「アップロードできませんでした」「『議事録』を削除しますか？」 |
| チェックボックス、選択肢 | 短い常体か名詞 | 「パスワードを記憶する」「次回から表示しない」 |
| 操作ログ | 体言止め | 「ユーザーを作成」「お知らせを削除」 |
| 個人ブログ、技術エッセイ | 書き手の文体のまま | だ・である調でも普通です |

一つの説明文の中で、です・ます調とだ・である調を混ぜないでください。説明文の文末を体言止めにすると素っ気なく見えるので、動詞で終えます。

**敬語は丁寧語を中心にし、尊敬語と謙譲語は効果がある所だけに使います。** 「ご確認ください」「お試しください」「お問い合わせください」は、ヘルプやエラーで自然に使われています。「ご確認いただけますようお願いいたします」「〜させていただきました」「〜でございます」は重く、内容が伝わりにくくなります。「確認してください」「〜しました」「〜です」で足ります。サポート窓口の文面のように「いたします」を基本にしている場合は、その体裁に合わせます。

**読み手を「あなた」と呼ばずに書きます。** 日本語では主語を省いても意味が通ることが多いです。持ち物を示すときは「お使いの」、本人を指すときは「ご自身」を使います。役割を区別したいときは「ユーザー」「管理者」「参加者」と書きます。「あなた」は、読み手本人と他の人を区別しないと意味が通らない場合だけに使います。「私たち」「弊社」もたいてい省けます。

**エラーでは、何が起きたかと次の操作を書きます。** 「〜できませんでした。〜してください。」が基本の形です。「〜に失敗しました」「〜は無効です」「不正な値です」は機械的で、読み手を責めるようにも聞こえます。「〜できませんでした」「〜は使用できません」「〜の形式が正しくありません」と書きます。全部を書く余裕がなければ、原因と対処を優先し、起きた事象は削ります。重大な障害でなければ「申し訳ございません」は付けません。

**確認では「〜しますか？」と聞きます。** 操作するのは読み手なので、「〜してもよろしいですか？」より「削除しますか？」の方が率直です。ダイアログのタイトルと実行ボタンには同じ操作の名前を使います。たとえば、タイトルが「『議事録』を削除しますか？」なら、ボタンは「削除」にします。

**回りくどい言い方を短くします。** 「〜することができます」は「〜できます」、「削除を行う」は「削除する」に縮めます。「〜することにより」は「〜すると」にします。ただし、助詞まで削ると読みにくくなります。「項目名変更します」は「項目名を変更します」と書きます。

**用語は一つの概念に一つだけ使います。** 一度「申し込み」と書いたら、同じ操作を「登録」「エントリー」と言い換えないでください。ボタン、見出し、メール、エラーで同じ言葉を使います。外部サービスの画面に出る名前は、そのサービスの表記のまま引用します。

**カタカナ語の長音は、採用した基準に合わせます。** 英語の語末が -er、-or、-ar の語は、文化庁の「公用文作成の考え方」、Microsoft、SmartHR のどれも長音符号を付けます（ユーザー、サーバー、コンピューター）。-y で終わる語は基準によって分かれます。公用文はカテゴリー、コミュニティーと伸ばし、Microsoft と SmartHR はセキュリティ、メモリと伸ばしません。Apple のサポート記事には今も「ユーザ」が残っています。プロジェクトに用語集があればそれに従い、なければ既存の文言に多い方にそろえます。製品名やサービス名は公式の表記を使います。

**数字は横書きなら半角の算用数字で書きます。** 大きな数は 3 桁ごとにコンマで区切り、「万」「億」は漢字にします（30 万円、1 億 2,000 万人）。「一度」「一部」「一時的」のように別の数に置き換えられない語は漢数字のままです。期間は「3 か月」と書き、「ヶ月」「カ月」は使いません。日付は「2024 年 3 月 14 日」、狭い場所では「2024/3/14」と書き、時刻は「12:30」のように半角のコロンでつなぎます。

**渡す前に日本語として確認します。** 次の点を確かめます。

- 説明文がすべてです・ます調で、ボタンと見出しに「。」や「です」が付いていないか
- 中国語の「，」「；」や、繁体字・簡体字の字形が混じっていないか
- 同じ概念が同じ言葉で書かれているか
- 長音、和欧間のスペース、全角と半角がファイルや画面の中でそろっているか
- プレースホルダーに名前や数字が入ったとき、前後の助詞や敬称（「{name}さん」など）が自然につながるか

## 書き換えの例

以下は自作の練習です。実在の製品やコミュニティの文章は引用していません。書き換えでは、元の文にある情報だけを使っています。

### エラーメッセージ

元の文：「アップロード失敗。ファイルサイズが不正です。」

書き換え：「ファイルをアップロードできませんでした。10 MB 以下のファイルを選んでください。」

10 MB という上限は、元の文の背景で確認済みの条件とします。上限が分からないときは数字を足さず、「ファイルサイズが上限を超えています」で止めます。

### 確認ダイアログ

元の文：タイトル「本当に削除してもよろしいでしょうか」、ボタン「OK」

書き換え：タイトル「『議事録』を削除しますか？」、説明「削除すると元に戻せません。」、ボタン「削除」

### お知らせメール

元の文：「山田様におかれましては、平素より格別のご高配を賜り、厚く御礼申し上げます。このたび、ご登録いただきましたイベントの会場が変更となりましたことをご報告させていただきます。」

書き換え：「山田様

ご登録いただいたイベントの会場が変わりました。」

イベント告知のメールなら、宛名のあとすぐ用件に入れます。取引先への書状のように形式が決まっている文面なら、元の挨拶を残します。

### 業務連絡

元の文：「お手数をおかけいたしますが、金曜日までに見積書のご修正をしていただけますと幸いでございます。」

書き換え：「お手数ですが、金曜日までに見積書を修正していただけますか。」

依頼であることと期限は残し、重ねた敬語だけを減らしています。

### 技術ブログ

元の文：「キャッシュを入れたら起動は速くなった。ただ、測ったのは手元の一回だけなので、本番でも同じとは限らない。」

書き換え：変更なし。

だ・である調は、個人の技術ブログでは普通の文体です。です・ます調に直す必要はありません。「手元の一回だけ」という限定も消さずに残します。

### 情報が足りないとき

元の文：「今回のアップデートで、かつてない快適さを実現しました。」

書き換え：「今回のアップデートで、動作を改善しました。」

外部に公開する文章で根拠が必要なら、「元の文には改善の内容や測定結果がありません」と書き添えます。数字や機能を書き足してはいけません。

## 参考

- 文化庁、[公用文作成の考え方（建議）（2022）](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93731901_01.pdf)。解説・広報はです・ます体を基本とし、過剰な敬語や「ございます」を避けます。長音、算用数字、3 桁区切りの基準もここにあります。官公庁向けの基準なので、プロダクトの文言はこれより口語的になります。
- Microsoft、[Japanese Localization Style Guide](https://download.microsoft.com/download/a/8/2/a822a118-18d4-4429-b857-1b65ab388315/jpn-jpn-StyleGuide.pdf)。4.1.8 Pronouns（「あなた」を避ける）、4.2 Style and tone（文体の使い分け、敬語、「〜しますか?」）、5.3.2 Error messages を参照しました。翻訳者向けの指針で、Microsoft 製品の表記を前提にしています。
- SmartHR Design System、[基本的な考え方](https://smarthr.design/products/contents/writing-style/)、[その他のUIテキスト](https://smarthr.design/products/contents/ui-text/app-writing/)、[エラーメッセージの基本的な考え方](https://smarthr.design/products/contents/error-messages/overview/)、[カタカナ語の表記](https://smarthr.design/products/contents/idiomatic-usage/katakana/)。ボタンは終止形かサ変名詞、見出しは名詞、説明文はです・ます調とし、過剰な敬語は避けるとしています。業務用 SaaS 一社の基準です。
- [Google アカウント ヘルプ「パスワードを変更する」](https://support.google.com/accounts/answer/41078?hl=ja)、[Apple サポート 102656](https://support.apple.com/ja-jp/102656)、[メルカリ ガイド「ゆうパケットポストの送り方」](https://help.jp.mercari.com/guide/articles/1083/)。いずれも手順はです・ます調で、「お使いの」「ご覧ください」を使っています。メルカリは「ご案内いたします」と丁寧さが一段高めです。Apple の記事には「あなた」と「ユーザ」も残っています。
