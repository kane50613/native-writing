# English punctuation by context

Choose punctuation for the surface and the writer's voice. A message bubble, a heading, and a paragraph have different ways of marking an ending.

## Choose the setting

| Setting | Working default |
| --- | --- |
| Books and edited essays | Punctuate complete sentences. Preserve deliberate rhythm, dialogue conventions, and the publisher's house style. |
| Blogs and long forum replies | Keep sentence boundaries, paragraphs, and useful asides. A web page can be as developed as a printed essay. |
| Short messages and casual replies | A standalone response can omit its final period when that fits the exchange. Keep internal punctuation that prevents misreading. |
| Documentation | Make conditions and steps unambiguous. Use consistent punctuation within each kind of list. |
| Interface and marketing copy | Short labels and headings usually need no final period. Supporting sentences still need clear boundaries; follow the product's style. |

## Marks and decisions

| Mark | What to preserve or adjust |
| --- | --- |
| Period `.` | End ordinary prose sentences. In a short social reply, adding one can change the perceived tone; this is contextual, not evidence that the writer is angry. Keep periods in abbreviations, decimal values, filenames, and code. |
| Comma `,` | Clarify clause structure, list items, and asides. In edited prose, connect independent clauses with a conjunction, separate them, or use a semicolon. Don't import Chinese comma-linked sentence structure mechanically. Follow the project's serial-comma convention. |
| Semicolon `;` | Keep it when it connects closely related complete clauses or separates complicated list items. It is available in books, blogs, and documents. In a brief chat message, a simpler break often fits better. |
| Colon `:` | Introduce an explanation, quotation, or list with a meaningful lead-in. Labels such as `Note:` follow their own convention. A colon does not make unrelated fragments into an explanation. |
| Question mark `?` | Mark a direct question, including a question used as a heading. An indirect report such as “She asked whether it worked” is not itself a question. A bare `?` or repeated `???` can convey impatience or disbelief in chat. |
| Exclamation mark `!` | Preserve actual enthusiasm or urgency. A friendly message can use one; neutral errors and instructions usually need the action explained instead. Repeated marks intensify the voice and should come from the writer or brief. |
| Quotation marks | Use them for speech, quotation, or a term under discussion. Follow the selected regional or publisher convention. Unnecessary scare quotes can introduce irony or doubt. |
| Apostrophe `'` / `’` | Preserve contractions and possession. Typographic apostrophes suit typeset prose; retain literal straight characters inside code and commands. Casual omission in a source message is not a rule to omit them in documentation. |
| Parentheses `( )`, brackets `[ ]` | Parentheses hold secondary information; brackets can mark editorial additions inside quotations. Keep important requirements in the main sentence. Balance ordinary prose parentheses, but recognize intentional emoticons. |
| Ellipsis `…` / `...` | Distinguish omitted quotation text, a fictional hesitation, and a conversational trailing-off. These uses need different judgment. Follow house style for spacing and dots rather than changing all occurrences globally. |
| Em dash `—`, en dash `–`, hyphen `-` | Preserve a real interruption or aside. Use range and compound-word conventions appropriate to the house style. These marks and the minus sign `−` are not interchangeable. |
| Slash `/`, tilde `~`, asterisk `*`, emoji | A slash can encode alternatives or units; spell out the relationship when ambiguous. Tildes, asterisks, and emoji may be tone or platform syntax. Keep URLs, paths, Markdown, and literal user input intact. |

## Books and dialogue

In conventional fiction editing, a dash can mark an abrupt interruption while an ellipsis can mark hesitation or speech trailing away. Replacing either with a period can change what happens in the scene. A change of speaker normally starts a new paragraph; preserve intentional experimental forms when the brief calls for them.

US-oriented styles commonly use outer double quotes and place commas and periods inside them. Oxford's UK house style uses outer single quotes and more context-dependent placement. Neither is a universal rule for every English publication. Preserve an established choice, and consult the publisher when preparing a manuscript to a specific standard.

## Original context checks

- Friendly chat reply: `sounds good, see you then` can stay as it is. There is no need to manufacture enthusiasm with `!!!`.
- Documentation: `The upload finished. Processing is still running.` keeps two distinct states, even though it appears online.
- Fiction: `“I thought you—”` and `“I thought you…”` describe different delivery. Choose from the intended interruption or hesitation, not a dislike of dashes.
- UI: heading `Upload complete`; body `We're processing your file.`; button `View uploads`. Read the strings together and follow the product's established punctuation.

Before delivering, check whether a punctuation change altered tone, scope, quotation boundaries, or literal syntax. A natural result need not use fewer marks.
