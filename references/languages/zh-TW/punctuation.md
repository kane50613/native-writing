# 台灣繁中的標點與場合

先判斷是在聊天、發文、寫文件，還是編書。同樣放在網路上，短留言、長篇攻略與小說試閱也會有不同寫法。[來源紀錄](sources.md)區分實際樣本、出版規範與本 skill 的編輯選擇。

## 先選場合

| 場合 | 起稿方式 |
| --- | --- |
| 書籍、散文、小說 | 正文完整分句；保留敘事節奏、對話停頓及出版社體例。書中引用聊天訊息時，可保留訊息的寫法。 |
| 部落格、長篇心得、攻略 | 依意思分段，條件和步驟要讀得清楚。可以親切，也可以用完整標點。 |
| Dcard 短留言、聊天、照片說明 | 一則訊息或一行已能收住意思時，可以不加末尾句號。沿用作者有作用的換行、表情和語氣。 |
| 文件、工作說明 | 句子及條件要清楚，不能為了像聊天而把多個步驟擠在一起。短確認訊息仍可簡短。 |
| 網站、app | 按鈕、欄位和短標題通常不加句號；多句說明仍需分句，沿用產品體例。 |

這是起點，不是每個看板的固定格式。Dcard 樣本裡既有不用句號的照片說明，也有使用句號、分號的旅遊攻略；同一篇底下的留言又可能不同。

## 各種符號怎麼判斷

| 符號 | 用法與情境 |
| --- | --- |
| 句號 `。` | 正文用來收住完整的意思。短訊息末尾可以省略，但不能因此刪掉長文內的分句。`好` 和 `好。` 的感覺可能不同，仍須看前後文與作者習慣。 |
| 逗號 `，`、頓號 `、` | 逗號交代句內停頓，頓號分開並列項目。聊天的空格與換行可以有節奏；一口氣講多件事時，仍要整理關係。不要把中文每個逗號都按英文獨立子句規則改掉。 |
| 分號 `；` | 適合分開有對應關係、內部又有逗號的句子。書籍、說明文章和攻略都可能用到；短留言通常不必刻意加。 |
| 冒號 `：` | 帶出說明、列舉或說話內容。標籤如「時間：」可以用；每個小標不必固定補冒號。 |
| 問號 `？`、驚嘆號 `！` | 保留疑問與情緒。`？`、`???`、`！！` 在對話裡可能是追問、驚訝或不耐煩，不能任意互換。想寫得客氣，先調整句子，不要只把問號換成波浪號。 |
| 引號 `「」`、`『』` | 台灣橫式正文通常外層用「」，內層用『』。完整引語與嵌在句中的片語，句尾標點位置不同。引述真實介面或他人的話，保留內容。 |
| 括號 `（）` | 放補充資訊，避免把關鍵條件藏進去。`（笑）` 或聊天裡故意不閉合的 `（` 可能是在表演口氣；依作者與場合保留，不主動塞進中性文案。正式正文要檢查配對。 |
| 刪節號 `……` | 編輯正文時用來表達省略、遲疑或話未說完，字形依出版體例。網路可見 `…`、`⋯⋯`、`...` 等形式，不必把聊天全部正規化；也不要把省略的引文誤當語助詞刪掉。 |
| 破折號 `──` / `——` | 用於轉折、插入說明、延長聲音等，字形與長度沿用出版社或專案體例。先判斷是否改變語意與節奏，再決定是否拆句。不能用它取代所有逗號。 |
| 書名號 `《》`、`〈〉` | 正文提到書刊、篇章等作品時，依體例標示。網路標題的 `【心得】` 是分類標記，不等於書名號；不必把每個標題都括起來。 |
| 連接號 `～` / `—`、斜線 `/` | 範圍符號與語尾的 `～` 功能不同。`週一至週五` 可避免歧義；時間、網址、路徑及單位內的符號照實際內容保留。 |
| 間隔號、專名號 | 姓名、書目和特殊排版按正式名稱與出版體例處理，不因看起來少見而替換。一般貼文不必另加專名號。 |
| 表情符號、`XD`、`（？` | 在部分社群中可以收尾、吐槽或表達不確定。保留原作者已有的作用，不當作所有台灣人都會用的配備。 |

中文正文優先使用適合的全形標點，英文句子及程式碼各依本身格式。手機輸入的半形問號不自動表示不自然；輸出到正式文件時才按體例統一。英文縮寫、小數點、版本號、URL、Markdown 與程式字串不做全文替換。

## 原創對照

同樣是約見面：

- 熟人聊天：先寫 `我到樓下了`，換行再寫 `你慢慢來`，不必補句號
- 工作說明：`請在下午三點前到一樓報到。報到後，工作人員會帶你入場。`
- 小說對話：`「我到樓下了。」她說。`
- app 按鈕：`通知對方`

短留言 `好好笑哈哈哈` 已經合用時就留下。公告 `週六暫停服務。週日恢復營業。` 也不用因為要貼上網就刪句號。

交稿前檢查：換行是否真能切開意思、問句還是不是問句、表情和重複符號有沒有改變情緒、引號與括號是否符合用途。長篇發文必要時補分段，不只減少標點。
