# 简体中文的标点与场景

先确定读者在读什么。聊天气泡、论坛长帖、帮助文档和小说正文不能只凭“都在网上”采用同一种标点。[来源记录](sources.md)区分书面规范、实际用例和编辑判断。

## 按场景选择

| 场景 | 起稿方式 |
| --- | --- |
| 书籍、小说、编辑过的散文 | 正文完整分句，保留人物说话的节奏与出版社体例。书里呈现聊天记录时，可以保留记录本身的形式。 |
| 博客、论坛长帖 | 按意思分段，保留有用的句内与句末标点。口语化不要求删除句号。 |
| 熟人聊天、短回复 | 一条消息已经表达完整意思时，可以不加末尾句号。较长消息仍需划清句子和条件。 |
| 文档、工作说明 | 保留步骤、因果、限制和列举层次。简短工作确认可以简短，正式说明则不能依赖读者猜停顿。 |
| 网站和应用 | 按钮、字段和短标题通常不加句号。正文说明按产品风格分句，问句仍可用问号。 |

## 各种符号的选择

| 符号 | 写作时怎样判断 |
| --- | --- |
| 句号 `。` | 结束陈述。短聊天中可由消息边界承担收尾；一个句号也可能让短回复显得更郑重或生硬，但不能仅凭符号推断情绪。保留作者稳定的习惯。 |
| 逗号 `，`、顿号 `、` | 分别处理语句停顿和并列项目。中文可以用逗号连接相关分句，不照搬英文的逗号规则；读者难以跟上时拆清关系。聊天空格可以保留，文档中的多项条件要写明确。 |
| 分号 `；` | 分开有层次的分句或复杂列举。小说、博客与长帖都能使用。短消息里不为显得严谨而硬加。 |
| 冒号 `：` | 引出解释、引语或项目。避免连续套用冒号让层级模糊；标签和表格按其格式处理。 |
| 问号 `？`、叹号 `！` | 保留提问、反问和情绪。正式正文按规范与语气使用；聊天的 `？`、`？？？`、`？！` 可能兼有催促或惊讶，改动前看关系和上下文。 |
| 引号 `“”`、`‘’` | 大陆横排正文通常外双内单。完整引语与句中引用片段分别处理收尾。已有品牌格式、实际界面和原文引用另行保留。 |
| 括号 `（）` | 补充信息或说明。文档要配对且指向明确；聊天中的表情、动作旁白或故意未闭合的括号按作者口吻判断。关键要求放在主句。 |
| 省略号 `……` | 区分引文删节、话未说完、犹豫和沉默。正式正文按体例统一；聊天里的 `...`、`。。。` 可能表达无奈等语气，不直接转成中性的句号。 |
| 破折号 `——` | 补充、转折、声音延长或话语中断均可能用到。小说里突然被打断与迟疑停顿不是同一件事，不把破折号一律改成省略号。 |
| 书名号 `《》`、`〈〉` | 按出版体例标示作品及嵌套引用。帖子标题里的 `【求助】` 是分类标签，不是所有标题都需要书名号。 |
| 连接号、间隔号、斜线 | 区分范围、型号、姓名和路径。用“至”或明确的连接词可减少范围歧义；专有名称和技术字符串保持准确。语尾 `~` 与数值范围不是同一种用法。 |
| 着重号、专名号 | 属于特定排版任务，按所采用的出版规范处理。普通消息不需要为了规范而主动加上。 |
| 表情、`~`、`[doge]` 等 | 属于特定交流习惯，可能表示玩笑、缓和或反讽。保留已有且合适的语气，不把它们当成简体中文的必需品。 |

规范细节以 GB/T 15834—2011 和项目体例为参考，社群习惯则从实际交流判断。中英文混排分别保留各自需要的标点；别把小数、时间、URL、代码和 Markdown 符号一起全角化。

## 原创对照

- 熟人短消息：`到了，门口等你` 可以不补末尾句号。
- 正式通知：`请在下午三点前到一楼报到。报到后，工作人员会带你入场。`
- 小说：`“我还以为……”她停住了。` 与 `“我还以为——”门铃打断了她。` 表现不同的停顿。
- 应用：标题 `上传完成`，说明 `文件仍在处理中。`，按钮 `查看文件`。

保持原稿的意思与情绪。既不要把长篇说明排成碎片，也不要把一句日常回复改成书面公文。
